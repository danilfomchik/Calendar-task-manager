# Home page redesign: decisions and design concepts

Spec: [issue #56](https://github.com/danilfomchik/Calendar-task-manager/issues/56). This document describes what shipped on `integration/home-redesign`. Domain terms (**Visible month**, **Month grid**, **Month swipe**, **Calendar filter**, **Dimmed event**, **Agenda panel**, **Bottom sheet**) are defined in `GLOSSARY.md`. Rules shared with the Day page are collected in `docs/design/overview.md`.

Scope: header, Month grid, day cells, event chips, sidebar, mobile layout. Not touched: Day page, Redux state shape and persistence, event data model. The event form modal was brought onto the tokens later (section 7).

## 1. Problems and decisions

| Problem                                                                                                            | Decision                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| A desktop day cell showed one event; height went to padding, the date row and a permanently reserved "N more" row. | Denser cell; the "N more" row exists only on real overflow.                                               |
| "Open day" / "add event" were hover-only: invisible on touch, unreachable by keyboard.                             | Primary actions moved to the Agenda panel (desktop) and the Bottom sheet's date row (mobile).             |
| Clicking a day did nothing on desktop; "N more" navigated away.                                                    | Click selects the day and opens the Agenda panel; "N more" does the same.                                 |
| Mobile stack (Week strip, tiny chevron, events list, pill button) felt clunky.                                     | Month grid always visible; events in a draggable Bottom sheet with the add button docked in its date row. |
| Hard-coded hex values, no identity, nothing for the Day page to inherit.                                           | Role-named dark tokens and a two-face type system.                                                        |

## 2. Key design concepts

1. **One selection model on both platforms.** The selected date is meaningful on desktop too. Selecting a day shows its events beside the grid (desktop) or over it (mobile). Nothing navigates away unless the user picks **Open day**.
2. **Two colour channels that never mix.**
   - _Calendar colour_: only event chips, dots and bars, via the `--calendar-color` custom property set from `getCalendarColor`.
   - _Interface colour_: only **green = action** (buttons, selection, focus) and **blue = info** (today).
     Calendar colours will become user-chosen, so they must never be mistakable for chrome.
3. **Today loud, selection quiet, one mark each.** Today is a filled blue numeral (no rule across its cell, no band across its week row). The selected day is the cell's 2px green frame and nothing else: the numeral belongs to today, the frame to selection, so a selected today is fill inside frame, never two marks on one element. (The selected numeral used to get a green underline as well; it doubled the selection mark and was dropped.) The sidebar mini-calendar uses the same split.
4. **Meaning is never colour alone.** Dimmed events use a dashed outline, no fill, hollow bar and faint italic text. A selected calendar has a green left bar as well as its dot ring. Cell buttons carry `aria-label` ("Monday 9 November, 3 events") and `aria-pressed`. Chips have a `title` with the calendar name.
5. **Calendar filter semantics are unchanged.** Empty filter = no filtering. A non-empty filter produces **Dimmed events**: visible, never hidden, non-interactive in the Agenda panel/Bottom sheet (`disabled`) and `aria-disabled` in the grid, where a click on a dimmed chip still selects its day (both use `isEventDimmed`). Sidebar counts ignore the filter.
6. **Square, hairline, technical.** No rounded cards; hairline borders; round shapes only for dots.

## 3. Visual system

### Tokens

Defined in `src/index.css` under `@theme`, dark only, named by role. Used as Tailwind utilities (`bg-surface-raised`, `border-line`, `text-text-muted`, `bg-action`, …).

| Role     | Tokens                                           | Values                                                    |
| -------- | ------------------------------------------------ | --------------------------------------------------------- |
| Surfaces | `surface-base`, `-sunken`, `-raised`, `-overlay` | `#0b0c0e`, `#08090a`, `#121417`, `#181b1f`                |
| Lines    | `line`, `line-strong`                            | `#22262b`, `#343a41`                                      |
| Text     | `text`, `text-muted`, `text-faint`               | `#f3f5f7`, `#a3acb6`, `#7d8791` (faint passes AA on base) |
| Action   | `action`, `action-ink`                           | `#35e08a`, `#04140b`                                      |
| Info     | `info`, `info-ink`                               | `#5aa2ff`, `#04101f`                                      |

Tokens are named by role, not value, so the Day page redesign can reuse them and a light theme later is a token change. No theme toggle. Hues may still be tuned.

Calendar colours are not tokens; they live in `defaultCalendars` (`src/services/constants.ts`): the Jewel palette, Work violet `#8b5cf6`, Personal magenta `#e046e8`, Health yellow `#facc15`, Holidays rust `#c2410c` (chosen over muted Earth and neutral Ink variants because its four hues separate best on the dark surface). Before it: orchid / purple / lemon / amber, and earlier Work `#4a6cf7` and Health `#34d399` until they were moved off the info blue and action green (see the colour rule in `overview.md`).

### Typography

Inter Tight for all text, plus Big Shoulders Display as the Headline voice for the month title (month heavy, year lighter), the Day heading numeral and the events total; no monospace face. The roles and the type scale are in `docs/design/typography.md`. Both load from one Google Fonts `<link>` in `index.html`. Month grid numerals carry the day's load by weight (see Day cell, desktop).

### Shared recipes

`src/services/styles.ts` holds the recipes Home reuses: `HAIRLINE_CONTROL_*` (square, line-strong, neutral hover: ‹ ›, Today, Open day, Change, Cancel, the panel and sidebar toggles), `PRIMARY_ACTION_CLASS` (the solid green action: Add event, Create event; the sheet's docked + is the same green as a 44px square), `ACTION_HAIRLINE_BASE_CLASS` (a green label on a hairline that turns green on hover and focus: Go to, the first-run Add to; for an action beside the page's one filled control, so a surface never shows two solid greens) and `TEXT_FIELD_CLASS` (square sunken field with a single green ring on focus). Icons are the SVGs in `components/ui/icons`, never Unicode glyphs.

### Motion and focus

- 150–200 ms, transform and opacity; no animation on page load. A base layer in `src/index.css` gives every `button`, `a[href]`, `[role=button]`, `summary` and `label` a 150 ms ease-out transition on colour, border, opacity, shadow and transform.
- Global `:focus-visible`: 2px `--color-action` outline, 2px offset, on every interactive element. It is unlayered CSS, so a utility that changes it needs `!` (`focus-visible:outline-offset-0!`); don't replace it with a 1px border or shadow.
- Global `prefers-reduced-motion` rule zeroes transition/animation durations, so state changes (the Agenda highlight, the Holiday chip's lit state) land instantly rather than disappearing; the Agenda panel and Popover entrances are CSS keyframes (`animate-panel-in`, `animate-popover-in`) so the same rule makes them land in place, and motion-library animations (Bottom sheet, Month swipe, Modal) also check `useReducedMotion`. `motion` stays off Home's first paint: the Bottom sheet and the Month swipe (`SwipeSlide`), its only Home users, are lazy-loaded and mobile-only, the swipe rendering the same rows in a plain grid until it arrives. Loading indicators are the exception: the `progress-pulse` utility (`src/index.css`) turns their spin or pulse into a slow 2 s opacity pulse in place (no movement, so not vestibular), so the Suspense spinner, the Holiday line skeleton and the Retry spinner still say "in progress" instead of becoming a static ring or grey bar.

## 4. Components

### Header (`pages/Main/components/Header`)

- Month/year is the large display title and the picker trigger (`CalendarDatePicker`, `aria-expanded`). The page's `<h1>` is an sr-only copy of it beside the trigger, since a heading can't contain the picker's popover.
- **Month picker** (the trigger's popover, a labelled dialog): the year between ‹ › (`text-h4`, tabular figures) over a 3×4 month grid, both in the body face (the popup resets the title's Headline face; Headline is kept for the month title, hero numerals and events total). Marks follow the Month grid: the visible month is the 2px green frame (selection), today's month (only in today's year) a blue fill on its label (today's numeral), so the visible month this month is frame plus fill. Picking a month shows it and **closes the picker**, returning focus to the title (Dropdown's `children` render function gets `close`); picking the visible month just closes. The year arrows move the visible month by a year at once and keep the picker open, so it always shows where the calendar is. Esc, a click outside and tabbing out close it as before. Keyboard: the dialog focuses the visible month; the month grid is one tab stop (roving tabindex), ←/→ by a month, ↑/↓ by a row, Home/End to January/December, Enter/Space picks. Month cells and year arrows are 44px on mobile (40px and 32px from `md`).
- **Picking a month never moves the selected day.** As with ‹ ›, a Month swipe or the mini-calendar's browsing, the picker changes only the visible month; the selected day is the user's own choice and the Agenda panel / Bottom sheet keep showing it. Moving it would silently pick an arbitrary day (the 1st? the same date?) and lose the one the user chose. Instead the selected day's "Not in view" cue carries a visible **Go to ›** chip back to it (see Agenda panel).
- Controls are demoted and fixed in place: ‹ Today ›, the green **Add event** and the **Agenda toggle**, always in that order, so opening or closing the Agenda panel never shifts the header (it used to swap Add event and the toggle in and out, and ‹ Today › glided). ‹ Today › is one segmented hairline control (`ChangeMonthControl`, chevron icons, inner dividers, the focus ring drawn inside each segment). Today (`hooks/useGoToToday`, shared with the T key) shows today's month, selects today and shows the Agenda panel for it (`openFor`, as selecting a day does), and dispatches `requestToday`, which resets the sidebar mini-calendar's month browsing; it is `aria-disabled` (dimmed, a click does nothing) while today's month is shown and today is selected, not `disabled`, so the click that brought the page to today never drops keyboard focus. **Add event** (`AddEventButton`) is the only filled control on the page and the page's one add action from `md`, panel open or closed; it creates on the selected date, which the open panel names. The **Agenda toggle** (`AgendaToggle`, the mirror of `SidebarToggle`) shows and hides the panel; its right rail is filled while the panel is shown, and it is the panel's only close control besides Esc. Every add path (header, sheet, N) goes through `hooks/useOpenCreateEvent`.
- **Skip link** (`MainLayout/SkipLink`, Home only): the page's first Tab stop, hidden until focused, "Skip to calendar" moves focus to the Month grid's wrapper, so the next Tab lands on the grid's one tab stop.
- No keyboard shortcuts for now: the ← / → / T / N page shortcuts (and the sidebar's switch for T and N) were removed from Home and the Day page and may come back as a planned feature. Arrow keys still move between days inside the Month grid, and Escape still dismisses the Agenda panel.
- **Month announcement** (`components/MonthAnnouncer`): one polite sr-only status region names the Visible month ("December 2026") whenever it changes after the page mounts, by the ‹ › buttons, Month swipe, Today, the month picker or the mini-calendar. Nothing is announced on arrival. The sidebar mini-calendar no longer announces the month it follows on Home; it speaks only when its own month-step buttons browse (on the Day page it still announces its month).
- Height `h-16` on mobile, `h-22` from `md` (exposed as `--height-home-header`).
- Mobile: no prev/next arrows (Month swipe covers it) and no header add button (the + docked in the Bottom sheet's date row does that); Today stays; touch targets are 44px.
- `SidebarToggle` (`components/common`): square, hairline, panel glyph with the rail filled when open, `aria-expanded`. On desktop it shows in the header only while the sidebar is closed (`md:hidden` when open) and in the sidebar header when open.

### Day cell, desktop (`Calendar/Day`, `DayEventsList`, `Event`)

- Header row: the numeral (20px, no leading zero), whose weight carries the day's load: bold full-strength text with events, regular muted text when empty (so free days recede), faint for a neighbouring month's day. No count badge. Padding `p-1.5`.
- **No separate load graphic.** The chips and "+N more" already say how full a day is, and the Agenda panel's Calendar mix breaks the selected day down by calendar, so the cell carries no gauge or wash. The earlier Day load bar and Load tint (a neutral wash stepped by event count) were removed: the tint read as background noise and the bar repeated the Calendar mix. A meter, an edge rail and a numeral-weight variant were tried and dropped for the same reason. A day with events still gets a bold numeral, an empty one a muted numeral.
- No current-week band: today is carried by its filled blue numeral alone; a band across the whole row was redundant. Weekends get no treatment either.
- Chips: 1.125rem high with a 0.125rem gap (18px and 2px at the default 16px root: the 12px caption with `leading-none` and 3px above and below), 3px calendar bar plus truncated title, on a translucent 6% `--color-text` fill. Height and gap are in rem like the caption, so when the user raises the browser's default font size the chip grows with its text instead of clipping it. On a coarse pointer (a touch tablet in the desktop layout, e.g. a landscape iPad with the sidebar closed) chips are 1.5rem (24px) high, the WCAG 2.5.8 minimum target, with the same gap: `DayEventsList` reads `(pointer: coarse)` live (`useCoarsePointer`) and uses that height for both the chips and the slot measurement, so fewer chips fit and the rest go to "+N more"; a mouse or trackpad keeps the 18px chips. No start time, because events have no time field and adding one is out of scope.
- Capacity is measured with a `ResizeObserver`: `floor((height + gap) / (chip + gap))`, with chip and gap converted from rem at the current root font size (`remToPx`, `services/dom`, via `hooks/useMeasure`), and every slot is a chip. "+N more" sits in the numeral row's free right side instead of taking a slot (just "+N" in a cell under 7rem, via a container query). At 1512×900 with both side panels open a cell shows 4 chips, where it showed 2 plus "+7 more" with 20px chips and a reserved slot. The 6×7 grid still fits one screen.
- **Narrow cells show bars, not chips.** From `md` to about 1100px with the Agenda panel open (and up to about 1200px with the sidebar open too) a cell is only 60–90px wide: chips cut titles to three to five letters ("Desig…"). `MonthGrid` measures its own width once (`useCompactCells`, a `ResizeObserver`, measured before paint) and, when a cell is under 5.5rem (88px at the default root, so it is in rem: with a raised browser font size the bars come in sooner), every cell lists its events as full-width chip miniatures with 2px gaps (the chip's neutral `bg-chip` fill with a 3px calendar-coloured leading edge, no title; solid 4px bars in full calendar colour read as a barcode) (`DayEventsList` with `variant="bars"`, `EventBar`). They fill the cell's height: as many as fit at a 7px minimum, sharing the free height up to a chip's 18px, so a busy day reaches the cell's bottom rather than stopping halfway and a one-event day is a chip-sized tile; the rest are counted by the same "+N" in the numeral row as chips use; a Dimmed event is a hollow bar. The bars are decorative: clicking anywhere in the cell selects the day and the Agenda panel lists its events by name. Closing the Agenda panel or the sidebar widens the cells and brings the chips back. At 1024×768 (sidebar open), 768×1024 and 1180×800 (sidebar open) the grid shows bars; at 1280×800 and wider it shows chips.
- With a Calendar filter on, matching events sort first in the cell (stable within each group), so the overflow hides Dimmed events rather than the ones the filter asks for.
- Days from neighbouring months: a light hairline hatch (135°, `--color-line` at 45%, 1px every 7px, the Calendar mix's hatch angle for "present, outside the current scope") over the sunken background, faint numeral, chips (or compact dots) at reduced opacity. The hatch is the channel that separates them: the sunken fill alone and the faint-versus-muted numeral step were too close, so at 1440 the October row read as November. It was `--color-line` at 70% every 6px until two full hatched rows (a month starting on Sunday, like November 2026, or December's tail) outweighed the month itself; the lighter hatch still reads as a texture, not a fill. The numeral stays `text-text-faint` (5.4:1 on the sunken fill, 5.0:1 where a stripe crosses a glyph; the 20px regular numeral is not large text, so it holds the 4.5:1 bar). The Calendar mix's own hatch (a filtered-out calendar's segment: its calendar colour at 40%, 2px every 5px) stays denser, since it has to read on a 3px bar. Same on mobile, where the hatched cells run together into one band at the grid's top and bottom.
- Empty month: when the Visible month has no events (per-month counts from `calendarsMap`, neighbouring months' days excluded) but events exist elsewhere, a quiet "Nothing planned this month" (`pages/Main/components/EmptyMonthNote`, caption, faint, plain text with no box) says so; it never takes clicks. From `md` it is a caption under the month title in the header, hanging in the header's lower padding so the title never moves (the picker's popover opens below it); it used to be a framed box floating over the third week's row, which read as a tooltip stuck on the grid and crossed the column hairlines. Never on **First run** (no events anywhere): the Agenda panel / Bottom sheet holds the one first-run state, and a note on an empty grid only repeated it (the old first run said "empty" three times at three sizes: Free day, "Your calendar is empty" and this note). On mobile, where cells have no borders, it is a single line in the gap between the third week's numerals and the fourth's (8px above the row boundary, 2px on a short phone), clear of both rows' numerals even at the 44px minimum row.
- Keyboard: the grid is one tab stop at every width (on mobile too, where the numerals were out of the tab order) (the selected day, or the Visible month's 1st when the selection is elsewhere); arrow keys move focus between numerals (a week per row, stopping at the grid's edges) and Enter / Space selects. Chips and "+N more" are out of the tab order, since the Agenda panel lists the selected day's events as buttons.
- Clicking anywhere in the cell, or the numeral button, calls `openFor(date)`. "+N more" does the same instead of navigating.
- Clicking a chip never opens the edit form: in a busy cell most of the area is chips, so aiming at the day used to start an edit. Its name says so: "Show <title> in agenda". The chip calls `showEvent(date, id)` (`AgendaPanelContext`): it selects the day like `openFor`, re-opens a dismissed panel, and highlights that event's row in the Agenda panel for 1.6 s (scrolled into view, a green frame and faint green wash that appear at once and fade out over 700 ms). Editing starts from the panel row. A dimmed chip is `aria-disabled`, not `disabled`, so it selects its day too; its title is text-muted, not faint, so it stays readable. The Bottom sheet has no chips (dots only), so mobile is unchanged: a tap selects the day.

### Day cell, mobile

- Weekday labels are two letters from the locale (`moment.weekdaysMin`: Mo Tu We Th Fr Sa Su), since single initials repeat (T T, S S).
- Numeral (`text-h6`, same weights as desktop; its button box is 28px tall instead of 32px, with a tighter head, on phones under 760px tall, where rows sit near their 44px minimum and the dots would otherwise cross the selection outline) plus the day's Calendar mix as dots (`DottedEventsList`): one dot per calendar with events that day, in the calendars' own order (as in the sidebar and the Calendar mix bar), hollow for a filtered-out calendar, up to four and a `+` when more calendars have events. Minimum height 44px.
- Tapping selects the date (tapping the Visible month's own date resets to today, as before). **Month swipe** is unchanged.

### Agenda panel (`AgendaPanel`, `AgendaPanelContext`)

- Right-hand panel, 340px (`w-85`), sunken surface, left hairline, hidden below `md`. Height is viewport minus the home header.
- Header (`AgendaHeader`): the date block (`DayHeading`, shared with the Bottom sheet at a smaller size): a 96px day numeral (`text-numeral-xl`) without a leading zero (blue when it is today; a link to `/day/YYYY-MM-DD`, "Open day, Monday 23 November", green on hover and focus, and outside the Bottom sheet's drag area) beside the weekday (plus a blue "Today") over `Month YYYY`; the block is the panel's (and sheet's) `<h2>`, an sr-only full date, since the visual pieces read badly in order, as in the Day page's Viewed day cell. There is no × in the panel: the header's Agenda toggle, directly above it, hides it (and Esc). When the selected day is not among the Month grid's cells (after ‹ ›, ← / →, a Month swipe or the month picker), a "Not in view" caption with a **Go to ›** chip (a 20px green hairline chip, `ACTION_HAIRLINE_BASE_CLASS`, widened to a 44px touch target by a pseudo-element, so the row never grows) sits under the month, inside the numeral's height so the row never grows (the Bottom sheet shares it through `DayHeading`, shortened to the Go to chip alone after the month, since its 56px numeral has no room for a third line; "Not in view" stays for screen readers); **Go to** shows the selected day's month and moves focus to its cell; the events total (`components/common/EventsTotal`, shared with the Day page) over the **Calendar mix**; then the **Holiday line**. An empty day's total reads **Free day** (`emptyLabel`) instead of "0 events", and its mix is left out with its 3px height kept, so the header never jumps between empty and busy days: the default landing is today, often empty, and its first impression should not be a zero over a dashed line.
  - **Calendar mix** (`CalendarMix`): a 3px bar with one segment per calendar, sized by its share of the day's events. No chips or labels: each event row already names its calendar, and the bar is decorative (`aria-hidden`). Counts ignore the Calendar filter; a filtered-out calendar stays in the bar hatched instead of filled, so filtering never changes the shape of the day. An empty day is a dashed hairline (where the mix is shown for one; the Agenda header and Bottom sheet show a spacer instead).
  - **Holiday line** (`HolidayLine`, chip view `HolidayLineChip`): a 32px row reserved only while AI insights are enabled. Skeleton while the selected date settles (400 ms) and loads, already labelled "AI ·" with a polite status region mounted with the row (so the wait says what it is for) (capped at 15 s, after which the row shows the error state), the holiday name as a hairline chip when there is one (a faint label, the name, a chevron), blank otherwise. The label says the line is AI output and whose holiday it is, "AI · Japan" or "AI · Worldwide" (just "AI" when the answer has no region), never a bare "Holiday": the model is not told the user's country, so a holiday is a fact about somewhere, not about the user. The region comes from a `region` field in the Groq JSON schema (one English country name or "Worldwide"); the popover repeats it under the name ("Observed in Japan"), as does the Day page's AI insights card. The chevron is always visible so the chip reads as clickable. Lit (hover, keyboard focus or open) the chip takes the raised fill, the chevron turns green and nudges right, and a green hairline draws across its foot; keyboard focus adds the global 2px green outline (it used to swap the outline for a 1px green border, too weak a focus indicator). Under reduced motion the same states appear without movement. While the popover is open the chip holds the lit look. When the request fails the row shows a static rose "Couldn't load AI insights" with a **Retry** button instead of going blank; while a Retry is in flight a spinner replaces the warning icon (a slow opacity pulse under reduced motion) (`components/ui/icons/WarningIcon`) and Retry is `aria-disabled` (a click does nothing) so it keeps keyboard focus; its focus ring is the global 2px green outline at offset 0, so it sits inside the rose row instead of merging with its border (it used to be a 1px rose ring); when a successful retry replaces the row, focus moves to the chip, or to the row if the line is now blank. The message is announced through a polite status region that stays mounted with the row (screen reader users otherwise never learn the line failed); since the line only requests once the date has settled, clicking through failing dates announces once, not per click. Selecting the chip opens a popover (`components/common/Popover`: portalled, right-aligned under the chip, about 340px, or full width with a 16px inset on each side below a 640px layout viewport, flips up when there is no room, one at a time, below modals) with the full AI answer in an editorial layout. It closes on outside click, Esc, focus leaving it, a modal opening and a date change; focus moves in on open and returns to the chip on close (to the Holiday line row if the chip has gone), except when focus itself moved to another control.
- Body: the day's full event list (`AgendaEvent`: calendar bar, semibold title, `Calendar · description`; selecting a row edits the event, its tooltip "Edit <title>"; no trailing Edit control; a row highlighted from a chip is framed in green), dimmed events per rule 5. Empty day (`AgendaEmpty`, shared with the Bottom sheet through its `placement` prop): the header already reads "Free day", so the body never says it again (the old "Nothing planned for Sunday." line is gone). It leads with the **Next event** row (`AgendaEmpty/NextEventLink`, `useNextEvent`): "Next ● Dentist Fri 13 Nov →", the first event after the day; then **After that** (`AgendaEmpty/AfterThat`, `getUpcomingDays` (`services/upcomingDays`, shared with the Day page's Upcoming) with `AFTER_THAT_LIMITS`: up to 5 days with events within 30 days after the Next event's day, 2 events per day plus "+N more", 8 in all): a caption heading over hairline-ruled rows, the date (`ddd D MMM`, muted, green on hover) in a fixed column beside the day's events as calendar-coloured dots and titles; a row is one button labelled with the day and its count. Both select their day through `useShowDay` (shows that month, selects the day, the Next event also highlights its row, then focus moves to the day's cell, since the empty body goes away), so a free landing reads as the days ahead and fills the column instead of leaving its lower part blank. When nothing comes later: "Nothing planned after 25 November." Both ignore the Calendar filter. **First run** (no events anywhere, `AgendaEmpty/FirstRun`) is the page's one empty state: "An event lands on the day you select. Pick one in the grid, or start with today." and, in the panel, a full-width green hairline **Add to 25 November** (`ACTION_HAIRLINE_BASE_CLASS`, `useOpenCreateEvent`; the only place the panel body adds, and only while the calendar is empty, so the header's Add event is not the sole, far-off way in; a hairline, not a second solid green, so the header's Add event stays the page's one filled control and the two never compete); in the sheet the line ends "or tap the + beside the date to add to today", pointing up at the docked +.
- Footer: the **Day note** (the shared `components/common/DayNote`: no frame, a 2px left rule, dashed with a note icon and "Add a note" while empty, solid once written, green with a raised fill while editing; it grows from 1 to 6 lines while editing; at rest a long note is clamped to 2 lines with a Show more / Show less toggle (expanded, up to 6 lines, then it scrolls, so the footer never pushes the panel or sheet past the screen), the row, empty or written, has a tight 4px block padding and no minimum height, and the autosave confirmation is a green check in a fixed slot at the right so it never reflows the text; a muted × at the far right removes the note in one click, no confirmation, and the Day page uses the same note), then a full-width hairline **Open 13 November** link (chevron at the right, to `/day/YYYY-MM-DD`). The panel has no add button of its own: the header's green Add event stays visible while the panel is open and adds to the selected day (the old hairline "Add to 23 Nov" read as a dim, secondary action).
- State lives in `AgendaPanelProvider`:
  - Open by default. `openFor(date)` selects the date and re-opens it; `close()`, the header's Agenda toggle and Escape dismiss it, and the toggle shows it again.
  - Escape closes only the topmost layer: the panel ignores it while a modal or menu is open (they close themselves), after a popover has handled it, and while a text field such as the Day note has focus.
  - Dismissal is the user's own choice; shrinking below `md` hides the panel without recording a dismissal, so it returns on resize back to desktop.
  - The Month grid takes the remaining width when closed (`flex-1 min-w-0`), so nothing overlaps or clips with the sidebar open or closed.
- Enter: 180 ms fade plus 24px slide, skipped under reduced motion.

### Bottom sheet (`BottomSheet`, mobile)

- Layer over the Month grid, `md:hidden`. The calendar reserves the peek (`useSheetPeek`: `SHEET_PEEK`, 329px, capped on short phones so the six week rows keep their 44px minimum; the budget is px at a 16px root, scaled to the root font size because the header, rows and sheet it measures are in rem, so a raised browser font size shrinks the peek before it covers the grid) as bottom padding so the grid is never covered while collapsed. Nothing else sits between the grid and the sheet.
- Two snap positions: collapsed (peek) and expanded (viewport height minus a 72px gap below the 64px header, so the sheet stops under the header). Expanded, a dimmed backdrop (the shared `Sheet` `modal` backdrop, as in the Day context Bottom sheet) covers the whole screen above it, header included (the layer is `fixed`, z-40, below the sidebar); it fades with the slide and the drag, and a tap on it or Esc collapses the sheet.
- Drag starts from the grab handle or the date header; release with velocity beyond ±250 px/s snaps in that direction, otherwise to the nearest half. Settling uses a spring; instant under reduced motion. A click within 150 ms of a drag end is ignored so a drag doesn't also toggle.
